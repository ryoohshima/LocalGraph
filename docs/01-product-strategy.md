# 製品戦略・ターゲット

## 1. 背景と課題

クラウド型 SaaS における情報漏洩事故の増加により、金融データ・機密データを第三者のサーバーへ送信することへの警戒感が高まっている。

一方で toB の現場（士業・医療・人事など）では、社内規約によりクラウドへのデータアップロードが禁止されている反面、Excel による手作業の集計・グラフ作成に限界が来ている。

## 2. 解決策

**利用者のデータをサーバーへ一切送信しない**、ブラウザ内完結型のデータ可視化ツール。
CSV/Excel をドロップし、列（ヘッダー）を割り当てるだけでダッシュボードが生成される。

## 3. ターゲット：士業・税理士事務所に一本化

### 3.1 toC（個人向け家計簿）を対象外とする理由

- マネーフォワード / Zaim の無料枠が既に市場を占有している。
- 「CSV を手動でダウンロードしてドロップする」手間こそ、自動連携サービスが勝った理由である。差別化にならない。
- 集客のフックとして無料提供する案もあったが、実態は**収益ゼロの製品をもう 1 つ運用する**ことになる。個人開発者に二正面作戦は成立しない。

### 3.2 マルチサブドメイン展開（医療 / 士業 / 人事）を見送る理由

コアエンジンが共通でも、**マーケティングと販路は業種ごとに完全に別物**になる。個人開発者が同時に 4 業種へ営業することは不可能。

### 3.3 士業を第一ターゲットとする理由

| 観点 | 士業・税理士 |
| --- | --- |
| ローカル処理の必然性 | **他人（顧問先）の金融データ**を扱うため最も高い |
| 予算 | 業務ツールを購入する習慣・予算がある |
| 到達性 | X・勉強会・士業コミュニティ経由で直接届く |
| 商用利用の判定 | 業務利用＝定義上すべて商用。課金対象が明快 |

医療（クリニック）は要求が最も厳しいが、**閉域網では Web アプリの初回ロードすらできない**ケースがあり、Web 配信モデルと相性が悪い。狙うならオフライン配布パッケージ版が前提となるため、初期スコープから外す。

## 4. 想定ユースケース

- 顧問先企業の通帳明細・試算表 CSV の可視化
- 資金繰りの推移グラフ
- 対前年比の比較
- 顧問先ごとのワークスペース切り替え
- 顧問先への報告用 PDF レポート出力

## 5. 訴求メッセージ

主訴求は「ローカルで安全」ではなく、**導入障壁の低さ**に置く。

> **インストール不要・稟議不要。URL を開くだけ。データは PC から出ない。**

競合分析および根拠は [05-feasibility.md](./05-feasibility.md) を参照。

## 6. スコープ外（現時点）

- toC 向け家計簿用途
- 医療・人事向け専用機能
- クラウド同期・チーム共有機能
- 銀行 API 連携等の自動データ取得
