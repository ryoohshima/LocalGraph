# 事業性の判断・リスク

## 1. 総合判断

**個人開発者による開発・運用は可能。成否は技術ではなく販路で決まる。**

| 観点 | 評価 | 理由 |
| --- | --- | --- |
| 実装難易度 | 低〜中 | 枯れた技術のみ。AI 前提で MVP 数週間 |
| 運用負荷 | **極小** | 静的配信 + API 1 本。利用者データを持たない |
| 賠償リスク | **極小** | 機密データを預からない |
| マネタイズ | 成立する | 通信あり方針への転換で強制力を確保 |
| 事業難易度 | **高** | ボトルネックは toB 営業 |

## 2. 競合：Power BI Desktop

直視すべき最大の競合は **Power BI Desktop**（無料・完全ローカル動作）である。「ローカルで安全」だけでは差別化にならない。

### 2.1 それでも残る市場

- **ソフトウェアのインストール権限がない**管理端末。ブラウザだけは使える。
- Excel は使えるが、BI ツール導入の稟議が通らない現場。
- Power BI の学習コストを払えない小規模事務所。

### 2.2 したがって訴求は導入障壁に置く

> インストール不要・稟議不要。URL を開くだけ。

「安全性」は購入を正当化する材料であり、興味を引くフックではない。順序を間違えない。

## 3. 最大のリスク：販売が開発ではない

本プロジェクトの工数の大半は toB 営業に費やされる。

- セキュリティチェックシートへの回答
- 請求書払い・見積書・注文書などの商流対応
- 長い検討期間
- 担当者の異動によるリセット

個人でも遂行可能だが、**これは開発タスクではない**。開発が終わっても事業は始まったばかりである、という前提で計画すること。

「通信先一覧・送信内容保証書」（[02-security-policy.md](./02-security-policy.md)）を早期に整備することで、この負荷の相当部分を定型化できる。

## 4. その他のリスク

| リスク | 影響 | 対応 |
| --- | --- | --- |
| 通信により情シスの審査対象になる | 導入期間の長期化 | オフラインライセンス版を用意 |
| ブラウザのストレージ削除でデータ消失 | 信頼失墜 | 起動時の警告表示 + エクスポート導線の明示 |
| 無料版のみで運用されてしまう | 収益化失敗 | 商用利用の明確な線引き。無料版を実務常用水準に置かない |
| CSV 方言への対応が無限に増える | 工数の泥沼化 | プリセット共有機能ではなく、汎用マッピング UI で吸収する |
| 士業市場に刺さらない | 事業停止 | 下記の撤退基準を参照 |

## 5. 進め方

1. 汎用 CSV ビューアとして無料版を公開し、士業コミュニティで反応を見る
2. 「通信先一覧・送信内容保証書」を先に整備する（営業資料兼、設計の制約仕様）
3. 有料機能（ワークスペース・前年比・PDF）を実装
4. 有償導入を数件獲得し、価格と機能を検証
5. 医療・人事への横展開は、士業で黒字化してから判断

## 6. 撤退基準

事前に決めておく。

- 無料版公開後、士業からの継続利用・問い合わせが得られない
- 有償化後、一定期間内に有償契約が獲得できない

この場合の失敗要因は技術ではなく市場であり、**判断が早く付くこと自体が本構成の利点**である。運用コストがほぼゼロのため、無料版を残したまま撤退することも可能。
